## 0. 何を作っているか

> Lanternは、クリエイターが創作を続けるための記録アプリです。
> 良い日もあれば、思うようにいかない日もある。
> アイデア、悩み、日常、発見。そのすべてが、創作という営みの一部です。
> Lanternは、それらを記録し、振り返り、自分だけの歩みを照らします。
> AIは答えを与えるためではなく、
> あなた自身が、自分の灯りを見つけるために寄り添います。

**主役は記録であり、AIは支える側である。**

要件を足すか迷ったときは「アイデア・悩み・日常・発見」の4つが
記録しやすくなるかで判断する。

## 1. 記録しやすさの4段

作者の定義。**すべての機能要件はこの4段のどれかに紐づく。**
紐づかないものは要件ではない。

| 段 | 内容 | 満たしている実装 |
|---|---|---|
| 1 開きたくなる | 世界観・今日の灯り | 起動画面（1日1回）・今日の灯り |
| 2 書き始められる | 一言の問い・空白を怖がらせない | 問いの資産50問・既定1欄のフォーム |
| 3 書き続けられる | 邪魔なUIがない | 折りたたみ・タブ1回で着くナビ |
| 4 書いてよかったと思える | 気づき・後で振り返れる | 保存後のAI応答・振り返り・カレンダー |

## 2. 画面構成（2026-08-12 改訂）

作者が用意したデザイン案（`DESIGN.md` と同梱の6画面）を踏まえて決めた。
**5タブ。iOS の上限なので、これ以上は増やせない。**

| # | タブ | 中身 | 4段 |
|---|---|---|---|
| 1 | ホーム | **今日の灯り** ＋ 直近の記録の一覧 | 1・4 |
| 2 | 記録 | 検索・カレンダー・全件・お気に入り ＋ **振り返り**（タブ） | 4 |
| 3 | **書く**（起動時に開く） | 記録フォーム / アイデア | 2・3 |
| 4 | 分析 | 記録した日・続いている日・年間マップ ＋ YouTube / Twitch | 4 |
| 5 | 設定 | | — |

**タブの外に2枚ある。** どちらも設定から1枚めくった先。

| 画面 | 中身 |
|---|---|
| `/account` | 自分が誰として使っているか。**アカウントの削除はここ** |
| `/plan` | いまのプランと、購入・復元。**2026-08-24 に追加**（`app/plan.jsx`） |

プランを別画面にしたのは、設定の行を2つに割らないため。
「現在のプラン」を押すとそこへ着く。**状態を見せる行そのものが入口。**
それまで購入できるのは断られた画面だけで、Apple の審査が
購入場所を見つけられず差し戻された（Guideline 2.1(b)）。

**起動時に開くのは「書く」。** 並びの1番目ではない。
一覧から始めると書くまでに1タップ増えるため、
「開いた画面でそのまま書き始められる」を優先する。

**今日の灯りはホームに置く。** デザイン案の Home は
「小さなラベル＋大きな一行」で始まり、そこに当たるのが今日の灯り。
**「書く」には置かない。** 同じものを2画面に置くと、
どちらが本体なのか分からなくなる。

**振り返りは「記録」のタブ。** 一度「インサイト」へ出したが、
記録と振り返りは同じ材料を見るものなので戻した（2026-08-12）。

**「分析」は継続の可視化と外部連携。** ただし**煽らない。**
数字は事実として出し、良し悪しを添えない。
入れないものは下記「やらないこと」。

「記録した日数」「続いている日数」は設定から移した。
設定は道具の手入れをする場所で、歩みを見る場所ではない。

**ホームと記録は、記録が少ないうちは似て見える。**
18件の現在はほぼ同じものが並ぶ。分かれるのは記録が増えてから。

### 一覧の作り

- 上から 検索欄 → チップ（すべて / 年 / お気に入り）→ カレンダー → 一覧
  - **年のチップは、記録がある年だけ出す。** 無い年を並べても押す理由がない
- 月ごとに1枚のカードを置き、**中を1pxの線で区切る**（最後の行には引かない）
  - `DESIGN.md` は "Avoid cards" と書いているが、2026-08-12 に作者が決めた
- 1行は 日付（見出しの役）＋本文の抜粋2行
- 月ごとの見出しを置く
- 日付は**相対表記**（今日 / 昨日 / それ以前は日付）
- **FAB は置かない。** 2026-08-13 に外した。
  「書く」がタブの中央にあり、どの画面からでも1タップで着く。
  同じ場所へ行く道を2つ作らない
- 一覧の下に「これより前の記録」（案の "Older entries"）

## 3. 機能要件

### F1 記録（必須）

- **1日3件まで**（2026-09-02 に1件から変えた）。**キーは `id`。日付ではない**
  - 「朝と夜で別のことを書きたい」という作者の要望。日付が鍵だと2件目が置けない
  - **無制限にはしない。** 数を絞らないと、記録アプリではなく作業ログに寄る
  - 上限は `main.MAX_RECORDS_PER_DAY`。**画面には出さない**（書く前に数を意識させない）
    - 例外は**上限に達したとき**だけ。書き終えてから 409 で断るより先に言う
- **「書く」の紙はいつでも白紙**（2026-09-03）。保存は必ず新しい記録として入る
  - 2026-09-02 は、その日の最後の記録を紙に載せて開いていた。
    **別のことを書くと前のが消えた**（同じ記録を書き直したことになるため）
  - 時刻の帯で選び直せるようにしたが、作者に「帯はいらない」と言われた。
    帯は、白紙で開かないことの埋め合わせでしかなかった
  - **直すのは「記録」タブ**（`components/LogDetail.jsx`）。
    書く場所と直す場所を分ける。どちらも一つのことだけをする
  - 記録のある日は、紙の上に一行だけ置く（数は書かない）。
    伝えるのは「ここに書いても前のは消えない」ことだけ
- **書くのは全画面**（2026-09-03・`app/write.jsx`）。作者の要望
  - 「書く」タブは**入口**。押すと上から被さり、「記録する」で保存して閉じる
  - 全画面に入るのは**記録まるごと**（日付・写真・保存）。作者の判断
  - **灯りと手がかりは入口の側**。どちらも「書いたあとに読むもの」で、
    書き終えると全画面は閉じているので受け取れない
  - 上限に達していたら入口が開かない。書き終えてから 409 で断らない
- **書く欄はひとつ。**「やったこと」だけ（2026-09-04・作者の指示）
  - よかったこと・困ったこと・次にやることの**欄は消した**
  - 3度置き直して動かなかった（畳む→チップ→紙の下の行＋キーボードの列）。
    記入率 次にやること 16.7% / よかった 5.6% / 困った 5.6%（2026-08 実測）。
    **置き方の問題ではなかった**——書いたあとに自分で分類させる形が、
    書く手を止めていた
  - 代わりに、**手がかりが詰まっている瞬間に一つだけ聞く**
    （`modules/ai.py`）。答えは「困ったこと」に入り、次の材料になる。
    「同じ入力に両方を負わせない」は元から書いてあった方針
  - **列は消さない**（`enjoyable` / `struggled` / `next`）。
    これまでの記録に中身が入っている。「記録」タブでは**読める**し、
    検索・書き出し・灯り・手がかりは4つとも見る
  - **直せるのも「やったこと」だけ**（2026-09-04・作者の指示）。
    直す側にだけ欄が残ると、消したはずのものが別の入口から生えてくる。
    触っていない3つは保存でそのまま送り直す（`LogDetail.jsx`）
- **書く場所はひとつ**（2026-09-04・作者の指示）。過去の日も全画面
  （`app/write.jsx` が `?date=` を受け取る）。記録タブの窓は消した。
  2か所に分けていたので、**片方だけ古くなっていた**——全画面には有る
  カードも灯りも手がかりも、窓には無かった
- 写真を1枚添えられる。**写真だけでも保存できる**
  - **写真は端末の中だけに置く。サーバーへ送らない**（2026-08-06〜）
  - Web では写真を扱わない（ブラウザに、消えない置き場所が無いため）
  - 端末を変えると写真は移らない
- 保存すると AI が応答を1つ返す
- 過去日の編集ができる
- 削除ができる（削除ボタンは赤）
- **「やったこと」だけ装飾できる**（太字・斜体・箇条書き）
  - 保存は Markdown。装飾を落としても読める文字列のまま残るため
  - **AI に渡す前に記法を剥がす。** 渡したままだと応答にも記法が混ざる
  - 残り3項目は素のテキスト。短いメモに道具立ては要らない
  - **画像の本文挿入と添付ファイルは入れない**（下記「やらないこと」）
- **お気に入りを付けられる。** 一覧で絞り込める
  - 数を表示しない。多い/少ないを評価しない
  - **記録の保存で触らない。** 専用の API（`PUT /api/logs/<date>/favorite`）が
    その列だけを書く。一緒にすると、編集するたびに星が外れる
  - `favorite` 列が無くても記録は読める（順番に依存させない）

### F2 問い（必須）

- 記録フォームのプレースホルダとして、書く前に1つ出す
- **AIを使わない。** 固定50問を日で巡回する
- **同じ日は同じ問いを出す。** リフレッシュボタンを置かない
- 今日の記録のときだけ出す。過去日の編集では出さない

### F3 アイデア（必須）

- **置き場所は「書く」タブの中**（2026-08-08 に「記録」から移した）
- 1行のメモ。日付に紐づかない
- 記録とは別テーブル
- 「使った」「戻す」ができる。**「完了」にしない**
- 使ったものは取り消し線で残す。**消さない**
- **件数を出さない**

### F4 振り返り（必須・「記録」のタブ）

- 今週・今月（ボタンを押したときだけAIが動く）
- 過去との対話（1/3/6/12ヶ月前）。常時は並べるだけ、押すとAIが観察を足す
- 頻出語（機械的な頻度処理のみ。感情分類をしない）
- 創作カレンダー（記録あり／なしの2状態）

### F5 分析（必須）

- 記録した日数・続いている日数を**数字のまま**出す
- **年間マップは持たない**（2026-08-14 に廃止）。
  カレンダーは「記録」タブに1つあれば足りる。2か所に置くと片方だけ直る
  - **2状態のみ。** 記録あり／なし。**濃淡を付けない**
  - 階調を入れると、薄い日が「足りない日」に見える
- **増減の矢印・進捗バー・達成率・比較を付けない**

### F5.1 外部連携（任意）

- YouTube / Twitch をタブで切り替える
- 数字は事実として出す。**評価しない・伸ばし方を提案しない**
- Twitch の過去配信は消えるため、取得できたときに保存する
- 連携を解除しても保存済みの配信は消さない

### F6 認証（必須）

- Supabase Auth（メール＋パスワード）
- Web でパスワード自動入力と Enter ログインが効くこと
- 401 で即ログアウトしない。更新して1回だけ再試行する
- **ログインと新規登録は別の画面**（`/login` と `/signup`）
  - 同じ画面でモードを切り替えると、どちらをしているのか分からない
- 新規登録では、押す前にパスワードの条件を出す
- 空欄のまま送らせない（Supabase の匿名ログインのエラー文が出てしまう）
- 確認メールを送ったあとは**宛先を画面に出す**。打ち間違いに気づく場所がここしかない
- 確認メールの再送を置く。届かないときに登録し直させない
- Supabase のエラー文はそのまま出さない。日本語の一文に置き換える
  （該当しないものは元の文を出す。握り潰すと無反応に見える）
- **パスワードの再設定ができる**（`/forgot` → メール → `/reset`）
  - 送ったあとは宛先を出し、再送を置く（新規登録と同じ考え方）
  - **登録済みかどうかを言わない。** 言うと、どのアドレスが
    登録済みかを外から数えられる
  - 戻り先は **Web に固定する。** アプリへ戻すにはディープリンクが要り、
    開かなかったときに**何も起きないように見える**
  - **`/reset` はセッションがあっても追い出さない。** 再設定のリンクは
    一時的なセッションを作るので、追い出すと変える前に画面が消える

### F7 設定（必須）

- 通知（毎日のきっかけ。既定は「切」）
- テーマ切り替え
- JSONエクスポート
- ログアウト・バージョン表示
- **アカウントの削除**（記録・アイデア・連携・認証をすべて消す）
  - App Store のガイドライン 5.1.1(v) が、アカウントを作れるアプリに
    アプリ内からの削除を求めている。無効化では足りない
  - 2段階の確認を置く。取り返しがつかないため
  - 端末内の写真は消えない（サーバーが存在を知らないため）

- **通知は催促にしない**（CLAUDE.md「習慣化の定義」）
  - 既定は「切」。**「入」にしようとしたときにだけ**許可を求める
  - 文面に**日数・件数・連続日数を出さない**。記録の中身も見ない
  - **今日すでに書いた日には送らない**（1回きりの予約を並べ、開くたびに作り直す）
  - 時刻は決め打ちの候補から選ぶ。**分は選ばせない**
  - サーバーは関与しない。プッシュトークンを取らない
  - Web では扱わない

- **アクティビティ（記録した日数・連続日数）は「分析」にある**（設定にはない）

プロフィール・AI設定は**要件に含まない**。

## 4. AIの要件

**AIができるのは2つだけ。**

1. 記録から読み取れる事実・パターンを観察して伝える
2. 答えを求めない問いを置く

助言・評価・意味づけ・物語化はしない。禁止ワードは CLAUDE.md にある。

| 要件 | 内容 |
|---|---|
| 長さ | 200文字以内を目安 |
| 形式 | Markdownを使わない。自然な日本語 |
| モデル | claude-sonnet-4-6 |
| 費用 | 記録の保存時と、ボタンを押したときだけ呼ぶ。定期実行しない |
| 灯り | 前日の記録がある日だけAI生成。無い日は固定文。離脱期間に触れさせないため、**入力データの構造で**禁じる（前日以外を渡さない） |
| 写真 | AIに渡さない |

## 5. やらないこと

| 対象 | 理由 |
|---|---|
| SNS分析（数字を伸ばす方法の提案） | 助言だから |
| フォロワー分析（数字での価値判定） | 評価だから |
| 才能判定・バズ予測 | 同上 |
| 自動コンテンツ生成 | 主役が記録でなくなる |
| AIエージェント | 同上 |
| ~~記録の複数件／日~~ | **2026-09-02 に開けた**（3件まで）。朝と夜で別のことを書けないのは、記録しやすさの4段の2に反していた |
| 目標設定機能 | v0.5 で構想したが、4段のどこにも効かない |
| 利用ログの収集 | 記録アプリが監視を始めることになる |
| 記録のタイトル | 書く前に「何の話か」を決めさせることになる |
| 添付ファイル・本文への画像挿入 | 置き場所がサーバーになる。2026-08-06 の判断（写真は端末の中だけ）と衝突する |
| 文字数カウンタ | 書きながら量を数えさせる |
| Streak の煽り（炎・進捗バー・カウントダウン） | 「見せるが煽らない」に反する |
| 他人との比較・順位（「上位15%」等） | **数字で人を評価する。最も遠い** |
| 総文字数と増減率 | 書いた量を成果として測ることになる |
| 気分の分類（Mood Balance） | 感情ラベルを付けない |
| 記録のタグ付け（#work 等） | 分類は「機械的な頻度処理」の外 |
| プロフィール（氏名・顔写真） | 1人で使う道具に要らない |
| セキュリティ設定・ヘルプセンター | 実装が無い。空の行を置かない |
| 羊皮紙のような地の質感 | `DESIGN.md` の地は `#F9F9FB`。**案が食い違うときは `DESIGN.md` が正** |

禁じているのは「数字に触れること」ではなく、
**数字を根拠に評価・判定・助言すること**である。

## 6. 非機能要件

| 項目 | 要件 | 現状 |
|---|---|---|
| 入力負荷 | 1分以内に記録できる | 満たしている（1記録の平均20.5字） |
| 対応環境 | Web / iOS / Android を同一コードから | 配布の状況は**現在地**を見る |
| データ | 利用者ごとに分離（`require_auth` で `g.user_id` に絞る） | 満たしている |
| 秘密情報 | コードに書かない。`.env` と Render から読む | 満たしている |
| 外部送信 | Anthropic / YouTube / Twitch 以外に送らない | 満たしている |
| 写真 | 端末の外に出さない | 満たしている |
| ログ | サーバーのログに記録の中身・user_id・資格情報を残さない | 満たしている（`test_privacy.py`） |
| プライバシーポリシー | 公開URLを持つ。ログイン不要で読めること | `client/public/privacy.html`（`PRIVACY.md` から生成） |
