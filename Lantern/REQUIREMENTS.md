## 0. 何を作っているか

> Lanternは、クリエイターが創作を続けるための記録アプリです。
> 良い日もあれば、思うようにいかない日もある。
> アイデア、悩み、日常、発見。そのすべてが、創作という営みの一部です。
> Lanternは、それらを記録し、振り返り、自分だけの歩みを照らします。
> AIは答えを与えるためではなく、
> あなた自身が、自分の灯りを見つけるために寄り添います。

**主役は記録であり、AIは支える側である。**

要件を足すか迷ったときは「アイデア・悩み・日常・発見」の4つが
記録しやすくなるかで判断する。

## 1. 記録しやすさの4段

作者の定義。**すべての機能要件はこの4段のどれかに紐づく。**
紐づかないものは要件ではない。

| 段 | 内容 | 満たしている実装 |
|---|---|---|
| 1 開きたくなる | 世界観・今日の灯り | 起動画面（1日1回）・今日の灯り |
| 2 書き始められる | 一言の問い・空白を怖がらせない | 問いの資産50問・既定1欄のフォーム |
| 3 書き続けられる | 邪魔なUIがない | 折りたたみ・タブ1回で着くナビ |
| 4 書いてよかったと思える | 気づき・後で振り返れる | 保存後のAI応答・振り返り・カレンダー |

## 2. 機能要件

### F1 記録（必須）

- 1日1件。日付をキーにする
- 4項目を持つ。**既定で見えるのは「やったこと」だけ**
  - やったこと / よかったこと / 困ったこと / 次にやること
  - 残り3つは「もっと詳しく書く」の中
  - **欄を減らさない。** 記入率5.6%でも使われており、後から分け直せない
- 写真を1枚添えられる。**写真だけでも保存できる**
  - **写真は端末の中だけに置く。サーバーへ送らない**（2026-08-06〜）
  - Web では写真を扱わない（ブラウザに、消えない置き場所が無いため）
  - 端末を変えると写真は移らない
- 保存すると AI が応答を1つ返す
- 過去日の編集ができる
- 削除ができる（削除ボタンは赤）

### F2 問い（必須）

- 記録フォームのプレースホルダとして、書く前に1つ出す
- **AIを使わない。** 固定50問を日で巡回する
- **同じ日は同じ問いを出す。** リフレッシュボタンを置かない
- 今日の記録のときだけ出す。過去日の編集では出さない

### F3 アイデア（必須）

- 1行のメモ。日付に紐づかない
- 記録とは別テーブル
- 「拾う」「戻す」ができる。**「完了」にしない**
- **件数を出さない**

### F4 振り返り（必須）

- 今週・今月（ボタンを押したときだけAIが動く）
- 過去との対話（1/3/6/12ヶ月前）。常時は並べるだけ、押すとAIが観察を足す
- 頻出語（機械的な頻度処理のみ。感情分類をしない）
- 創作カレンダー（記録あり／なしの2状態）

### F5 外部連携（任意）

- YouTube / Twitch をタブで切り替える
- 数字は事実として出す。**評価しない・伸ばし方を提案しない**
- Twitch の過去配信は消えるため、取得できたときに保存する
- 連携を解除しても保存済みの配信は消さない

### F6 認証（必須）

- Supabase Auth（メール＋パスワード）
- Web でパスワード自動入力と Enter ログインが効くこと
- 401 で即ログアウトしない。更新して1回だけ再試行する

### F7 設定（必須）

- 記録した日数・現在の連続日数
- テーマ切り替え
- JSONエクスポート
- ログアウト・バージョン表示

プロフィール・通知・AI設定は**要件に含まない**。

## 3. AIの要件

**AIができるのは2つだけ。**

1. 記録から読み取れる事実・パターンを観察して伝える
2. 答えを求めない問いを置く

助言・評価・意味づけ・物語化はしない。禁止ワードは CLAUDE.md にある。

| 要件 | 内容 |
|---|---|
| 長さ | 200文字以内を目安 |
| 形式 | Markdownを使わない。自然な日本語 |
| モデル | claude-sonnet-4-6 |
| 費用 | 記録の保存時と、ボタンを押したときだけ呼ぶ。定期実行しない |
| 灯り | 前日の記録がある日だけAI生成。無い日は固定文。離脱期間に触れさせないため、**入力データの構造で**禁じる（前日以外を渡さない） |
| 写真 | AIに渡さない |

---

## 4. やらないこと

| 対象 | 理由 |
|---|---|
| SNS分析（数字を伸ばす方法の提案） | 助言だから |
| フォロワー分析（数字での価値判定） | 評価だから |
| 才能判定・バズ予測 | 同上 |
| 自動コンテンツ生成 | 主役が記録でなくなる |
| AIエージェント | 同上 |
| 記録の複数件／日 | 1日1件＋アイデア複数で足りる |
| 目標設定機能 | v0.5 で構想したが、4段のどこにも効かない |
| 利用ログの収集 | 記録アプリが監視を始めることになる |

禁じているのは「数字に触れること」ではなく、
**数字を根拠に評価・判定・助言すること**である。

## 5. 非機能要件

| 項目 | 要件 | 現状 |
|---|---|---|
| 入力負荷 | 1分以内に記録できる | 満たしている（1記録の平均20.5字） |
| 対応環境 | Web / iOS / Android を同一コードから | Web のみ配布済み |
| データ | 利用者ごとに分離（`require_auth` で `g.user_id` に絞る） | 満たしている |
| 秘密情報 | コードに書かない。`.env` と Render から読む | 満たしている |
| 外部送信 | Anthropic / YouTube / Twitch 以外に送らない | 満たしている |
| 写真 | 端末の外に出さない | 満たしている |
| ログ | サーバーのログに記録の中身・user_id・資格情報を残さない | 満たしている（`test_privacy.py`） |
| 検査 | pytest + vitest。認証ガードは全ルート走査で固定 | 578 + 82 件 |

## 7. 要件を変えるときの手順

**このファイルを先に直す。** 実装してから書くと、実装できたものが要件になる。

1. 4段のどれに効くかを書く
2. 効かないなら足さない
3. CLAUDE.md の禁止事項と衝突しないか見る
4. 衝突するなら、実装ではなく**どちらの文書が正しいか**を先に決める
